# Markdown 常用语法笔记

Markdown（文件扩展名 `.md`）是用普通文字和少量符号记录内容的方式。你只需要在文字旁边加上 `#`、`**` 等符号，Obsidian 就能显示标题、加粗、列表和图片。

**使用方法：先看灰色代码框里的写法，再复制到自己的笔记中，替换示例文字。** 代码框用于展示语法，其中的标题、链接等不会真正生效。

> [!tip] 刚开始先掌握这些
> 标题、段落、加粗、列表、代码块、笔记链接和图片，已经足够记录大部分 Java 学习笔记。后面的表格、提示框和公式可以用到时再查。

通用 Markdown 适用于很多软件；本文明确标注的 Obsidian 扩展，例如 `[[笔记链接]]`、`==高亮==` 和提示框，换到其他软件时可能显示不同。

## 一、最常用的写法

| 想实现的效果 | 输入示例 |
| --- | --- |
| 一级标题 | `# Java 集合` |
| 二级标题 | `## ArrayList` |
| 三级标题 | `### 扩容机制` |
| 加粗 | `**重要知识点**` |
| 斜体 | `*补充说明*` |
| 删除线 | `~~旧结论~~` |
| 高亮（Obsidian 扩展） | `==需要复习==` |
| 行内代码 | `` `ArrayList` `` |
| 无序列表 | `- 一个知识点` |
| 有序列表 | `1. 第一步` |
| 未完成任务 | `- [ ] 复习集合` |
| 已完成任务 | `- [x] 看完代码` |
| 引用 | `> 摘录的一句话` |
| 笔记链接（Obsidian 扩展） | `[[笔记名称]]` |
| 图片嵌入（Obsidian 扩展） | `![[图片.png]]` |

符号一般使用**英文半角符号**。`#`、`-` 和列表序号后面记得加一个空格。

## 二、标题与段落

### 标题如何分级

```markdown
# Java 集合

## List

### ArrayList

#### 扩容机制

## Set
```

`#` 的数量代表层级，最多 6 级。建议每篇正文只写一个一级标题，章节用二级标题，章节内的小节用三级标题。

**正确：** `# Docker`，井号后有空格。

**容易写错：** `#Docker`，缺少空格，可能被 Obsidian 当作标签，不能作为标题显示。

Obsidian 可能同时显示文件名和正文中的一级标题，看起来像重复标题。可以只保留其中一种呈现方式，不需要因此修改全部章节层级。

### 正文和换段

```markdown
这里是第一段，可以直接写普通文字。

这里是第二段。两段之间空一行。
```

日常写笔记时，**段落之间空一行**最稳妥。不要用许多空格来对齐内容，也不要用大量空行模拟 Word 的分页。

如果只想在同一段内换行，可在上一行结尾输入两个空格后再回车。单次回车的显示效果还会受 Obsidian 的“严格换行”设置影响。

## 三、强调与行内代码

```markdown
**重点：先理解原理，再记 API。**

*这是一句补充说明。*

~~这条结论已经过时。~~

==下次复习时重点看这里。==

创建对象可以使用 `new`，比较对象时注意 `equals()`。
```

显示示例：

**重点：先理解原理，再记 API。**

*这是一句补充说明。*

~~这条结论已经过时。~~

==下次复习时重点看这里。==

创建对象可以使用 `new`，比较对象时注意 `equals()`。

反引号是 `` ` ``，通常在键盘左上角 Esc 下方的按键上；它不是单引号 `'`。

## 四、列表和待办事项

### 无序列表与缩进

```markdown
- Java 基础
    - 面向对象
    - 异常处理
- 数据库
    - MySQL
```

显示示例：

- Java 基础
    - 面向对象
    - 异常处理
- 数据库
    - MySQL

子项前面可输入 4 个空格。编辑列表时也可用 Tab 增加缩进、Shift+Tab 减少缩进。

### 有序列表

```markdown
1. 阅读概念
2. 运行示例
3. 记录问题
```

### 待办清单

```markdown
- [ ] 复习 HashMap
- [ ] 手写一个示例
- [x] 整理 ArrayList 笔记
```

显示示例：

- [ ] 复习 HashMap
- [ ] 手写一个示例
- [x] 整理 ArrayList 笔记

注意 `-` 后面的空格，以及未完成任务方括号中间的空格。

## 五、多行代码：Java、SQL 和命令

写多行代码时，用三个反引号包住代码。第一行反引号后面可以写语言名，最后一行再写三个反引号结束。

Java 的完整输入写法：

````markdown
```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
```
````

显示效果：

```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
```

SQL 的写法：

````markdown
```sql
SELECT id, name
FROM users
WHERE id = 1;
```
````

命令的写法：

````markdown
```powershell
java -version
```
````

常见语言名：`java`、`sql`、`javascript`、`html`、`css`、`json`、`yaml`、`bash`、`powershell`。不需要高亮时可写 `text`。

> [!note] 代码块里的符号不会变成排版
> 代码里的 `#`、`*`、`<img>` 等会原样显示。Obsidian 的普通代码块用于记录代码，不会因为打开笔记而执行其中的 Java、SQL 或命令。

## 六、网页链接和笔记链接

### 网页链接

```markdown
[Obsidian 官方帮助](https://obsidian.md/help)
```

显示效果：[Obsidian 官方帮助](https://obsidian.md/help)

方括号中写想显示的文字，圆括号中写网址。

### 链接到仓库内的笔记（Obsidian 扩展）

```markdown
[[Java基础]]

[[java/java基础]]

[[java/java基础|查看 Java 基础笔记]]
```

`[[...]]` 指向笔记；竖线 `|` 后面的内容是显示名称。输入 `[[` 后，优先从 Obsidian 的提示列表选择已有笔记，减少文件名输入错误。

上面的 Java 路径只是示例，新仓库中未必有这篇笔记。请替换为自己仓库中的文件。点击尚不存在的笔记链接可能会创建新笔记。

### 链接到标题

```markdown
[[Java基础#变量]]

[[#五、多行代码：Java、SQL 和命令]]
```

第一种指向其他笔记的标题，第二种指向当前笔记的标题。本页的“快速查找”就是可点击的标题链接。

### 显示另一篇笔记的内容

```markdown
![[Java基础#变量]]
```

在链接前加 `!` 表示嵌入内容。普通 `[[...]]` 主要用于跳转，`![[...]]` 用于把内容直接显示在当前笔记中。

## 七、图片：显示、打开和调整大小

### 直接显示仓库内的图片

```markdown
![[附件/集合结构.png]]
```

假设仓库中存在 `附件/集合结构.png`，这行就能直接显示图片。请使用图片的真实路径；本模板没有附带名为“集合结构.png”的图片。

日常操作可以把图片拖入笔记，或复制图片后粘贴进笔记，让 Obsidian 帮你生成引用。

### 缩小显示，但保留原图清晰度

```markdown
![[附件/集合结构.png|500]]
```

`500` 表示显示宽度为 500 像素，高度按原图比例调整。这只改变笔记里的显示大小，不会压缩或修改图片文件。

### 只显示“打开原图”链接

```markdown
[[附件/集合结构.png|打开原图]]
```

没有前面的 `!`，就显示文件链接。Obsidian 1.13 起提供原生全屏图片查看器，可点击图片或缩放按钮查看细节；旧版本的交互可能不同。

### 通用 Markdown 图片写法

```markdown
![集合结构示意图](附件/集合结构.png)
```

这种写法的路径通常相对于当前笔记。Obsidian 的完整库内 Wikilink 路径则从仓库根目录开始，例如 `![[java/_attachments/java基础/media/image1.png]]`。

同名图片较多时，应写完整的库内路径。文件移动或改名优先在 Obsidian 内操作，并在设置中开启自动更新内部链接。

> [!tip] 记录图片时优先用原生嵌入
> 在 Obsidian 中优先使用 `![[图片路径]]`。HTML 的 `<img ...>` 虽然可能显示图片，但在实时预览里选中后可能露出 HTML 源码，且交互与原生图片不同。

## 八、表格

适合记录接口区别、复杂度对比和参数说明。

```markdown
| 集合 | 底层结构 | 查询特点 |
| --- | --- | --- |
| ArrayList | 动态数组 | 按索引查询快 |
| LinkedList | 双向链表 | 按索引需遍历 |
```

显示效果：

| 集合 | 底层结构 | 查询特点 |
| --- | --- | --- |
| ArrayList | 动态数组 | 按索引查询快 |
| LinkedList | 双向链表 | 按索引需遍历 |

第二行 `| --- | --- | --- |` 是表头分隔行，不能省略。单元格宽度不用靠空格对齐。

设置对齐方式：

```markdown
| 左对齐 | 居中 | 右对齐 |
| :--- | :---: | ---: |
| 文字 | 文字 | 123 |
```

表格内部的文字如果本身含有 `|`，要写成 `\|`，否则会被误认为分列。例如在表格里写图片尺寸时：

```markdown
| 名称 | 示例 |
| --- | --- |
| 集合图 | ![[附件/集合结构.png\|300]] |
```

多行代码和很长的解释通常放在表格外更容易阅读。普通 Markdown 表格不支持随意合并单元格。

## 九、引用和提示框

### 普通引用

```markdown
> 这里是从资料中摘录的一句话。
> 第二行也在前面加上大于号。
```

显示效果：

> 这里是从资料中摘录的一句话。
> 第二行也在前面加上大于号。

### 提示框（Obsidian 扩展）

```markdown
> [!tip] 我的记忆方法
> 先写一个最小示例，再对照源码看实现。
```

显示效果：

> [!tip] 我的记忆方法
> 先写一个最小示例，再对照源码看实现。

常用类型：`note`（说明）、`tip`（提示）、`warning`（注意）、`question`（疑问）、`example`（示例）。

默认折叠的问题与答案：

```markdown
> [!question]- 为什么这里使用接口类型？
> 方便替换实现，并减少代码对具体实现的依赖。
```

`-` 表示默认折叠，`+` 表示默认展开。

## 十、标签、分隔线和注释

### 标签（Obsidian 扩展）

```markdown
#Java #待复习 #Java/集合
```

标签便于集中查找相关笔记。标签内部不要有空格。`# Java` 是标题，`#Java` 才是标签。

### 分隔线

```markdown
上半部分内容。

---

下半部分内容。
```

分隔线前后空一行。文件最开头成对的 `---` 也可能用于属性区；初学时不要把它与正文分隔线混淆。

### 注释（Obsidian 扩展）

```markdown
%% 这里留给自己：这段还需要再核实。 %%
```

注释会保存在文件中，阅读视图中隐藏。它不是保密工具，分享 `.md` 文件时，对方仍然可以查看注释内容。

### 原样显示特殊符号

```markdown
\# 这行不会变成标题

\*这两个星号按原样显示\*
```

反斜杠 `\` 可以取消后面某些符号的排版含义。解释语法时，把示例放进代码框通常更方便。

## 十一、公式和脚注

这一部分用到时再查，不影响日常记录。

行内公式的写法：

```markdown
数组下标范围可以写成 $0 \le i < n$。
```

独立公式的写法：

```markdown
$$
T(n) = O(n \log n)
$$
```

脚注的写法：

```markdown
这条结论还需要结合适用条件理解。[^条件]

[^条件]: 在这里补充适用条件或资料来源。
```

数学公式与脚注的支持情况取决于 Markdown 软件；Obsidian 支持这些写法。

## 十二、如何使用学习笔记模板

仓库的 `模板` 文件夹中还准备了 **学习笔记模板**，适合直接开始写一篇新知识点。

1. 在 Obsidian 中新建一篇空白笔记，并先起好文件名。
2. 打开命令面板，搜索“插入模板”或 `Templates: Insert template`。
3. 选择“学习笔记模板”。
4. 填写概念、示例、易错点和复习清单；不需要的小节可以删除。

模板使用时会插入正文到光标位置，不会自动替换整篇笔记。插入前最好让笔记保持空白。

模板里的 `{{title}}` 会替换为当前笔记名，`{{date}}` 会替换为当天日期。请通过“插入模板”使用；直接复制粘贴这些变量不会自动替换。

如果命令不可用，在“设置 → 核心插件”确认“模板”已启用，再把模板文件夹位置设为 `模板`。

本速查笔记也存放在模板文件夹中，因此可以在模板选择列表里找到。**日常查阅直接打开本笔记即可，不必把整篇速查表插入每篇学习笔记。**

## 十三、常见问题排查

| 问题 | 先检查这里 |
| --- | --- |
| 标题没有变大 | `#` 后面是否有空格；是否在代码块内部 |
| 后面整篇都变成代码 | 是否漏写代码块结尾的三个反引号 |
| 图片只显示一个链接 | 是否漏掉了最前面的 `!` |
| 图片无法显示 | 图片是否实际存在；路径和文件名是否正确 |
| 点击图片看到 HTML | 是否使用了 `<img>`；优先改用 `![[图片路径]]` |
| 图片打开的是另一张 | 图片是否重名；改用完整的库内路径 |
| 表格错列 | 是否漏了表头分隔行，或文字中含未转义的竖线 |
| 列表没有分层 | 子项前面是否有足够缩进 |
| 笔记链接显示为不存在 | 文件是否在当前仓库，名称是否匹配 |
| 加粗符号露出来 | 左右 `**` 是否成对；是否选中了该段、正在编辑源码 |
| 模板变量没有替换 | 是否通过“插入模板”命令插入，而非普通粘贴 |

实时预览会在编辑某些内容时显示源语法，这通常不是文件损坏。想专心阅读时可以切换到阅读视图；想核对所有标记时可使用源码模式。
